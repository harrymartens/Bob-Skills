# IBM product documentation MCP server — feasibility probe

Date: 2026-11-04. All evidence is from live `curl` requests made from this session (outbound via the agent proxy). Raw responses are saved under
`/tmp/claude-0/-home-user-Bob-Skills/b342c007-b76f-5ffe-9fc5-ab63ba919308/scratchpad/ibm-docs-probe/` (treated as untrusted data; inspected with grep/head and `python3 -I` only).

## Verdict: **feasible-with-caveats**

IBM Documentation (www.ibm.com/docs) exposes an unauthenticated JSON search API and an unauthenticated topic-content API that return real article HTML to a plain HTTP client. A small MCP server with two tools (`search_ibm_docs`, `fetch_ibm_doc`) plus optional `get_toc` / `list_products` is straightforward. The caveats are: (1) the API is undocumented and `robots.txt` lists `Disallow: /docs/api` (a crawler signal, not an auth wall); (2) Akamai Bot Manager 403s several common HTTP-library default user agents, so the server must send an accepted UA string; (3) product landing pages are JS shells / "Bot Index" pages, so only topic pages and the API should be used for content.

## Recommended approach

**Search tool** — `GET https://www.ibm.com/docs/api/v1/search?query=<q>&lang=en&start=<n>&limit=<10..25>&products=<KEY[,KEY]>&fallback=true`
- Return `title` (strip `<b>`), `snippet` (strip `<b>`), `fullurl`, `href`, `product.key`, `product.label`, `productBreadCrumb`, `date`, plus `hits`/`next` for pagination.
- Optional product scoping: resolve a product name to a key via cached `GET /api/v1/products` (1,225 entries, 131 KB; `productUrlKey` like `db2`, `bobz`, `wx-code-assistant`) and version-specific keys from `/api/v1/product/<KEY>` or from search results' `product.key` (e.g. `SSEPGG_12.1.0`, `SSRD57H_3.0.0`, `SSGUM3_5.3.x`). `/api/v1/suggest` gives product hints and query completions.

**Fetch tool** — `GET https://www.ibm.com/docs/api/v1/content/<href>` where `href` is the search result's `href` (e.g. `SSEPGG_12.1.0/com.ibm.db2.luw.messages.db2.doc/doc/rdb2msg.html`). Also accept a pretty `…?topic=…` URL (fetch it directly: topic pages are server-rendered with the same `<article>`), and detect the "`- Bot Index`" title / 3 MB fallback as "topic not found".
- HTML → text: take `<main>`/`<article>`, drop `<script>`/`<style>`/`<aside role="complementary">` (child-link lists) or keep them as "See also"; convert with a small HTML→Markdown step (tested: stdlib `html.parser` yields clean prose; headings `h1.topictitle1`, `.shortdesc`, `<pre>`/`<code>` for syntax, `<table>` for option tables). Rewrite relative links (`../doc/x.html`) against the href's directory into `https://www.ibm.com/docs/api/v1/content/<dir>/x.html` or into the canonical `?topic=` URL from `<link rel="canonical">`. Keep `<meta name="description">` as a summary.
- Extras: `GET /api/v1/toc/<KEY>` (full tree with `href`s — large: Db2 12.1 is 3.1 MB / 17,796 nodes; cache and offer `get_toc(product, depth, section)`), `otherversion?href=` to switch versions, `breadcrumb/<href>` for context, `product.pdfDocumentation` for a whole-product PDF when present.
- Client config: send `User-Agent: Mozilla/5.0 (compatible; <name>/<ver>; +<url>)` (or Go/curl-style); send `Accept: application/json` for API calls; cache responses (server sets `max-age=3600`); keep concurrency low (no rate-limit headers observed, 10 sequential calls all 200).

**IBM Bob (bob.ibm.com)** — fetch pages directly (server-rendered HTML with `<article>`), enumerate via `https://bob.ibm.com/sitemap.xml` (187 English `/docs/` URLs) and `https://bob.ibm.com/llms.txt`. There is no public search endpoint, so a Bob-docs search would need a local index built from the sitemap (small: ~190 pages) or a fallback to `www.ibm.com/docs` search with `products=SSRD57H_3.0.0` for the Z premium package.

## Known blockers / caveats

1. **Undocumented API + robots `Disallow: /docs/api`.** No official terms or documentation for `ibm.com/docs/api/v1` exist (IBM help page only says search "uses APIs"). Treat as unstable; the current signature was read from `index_bundle.js` and the `hkwd` README notes earlier field changes. Use conservative, cached, low-volume access and identify the client honestly.
2. **Akamai Bot Manager UA filtering.** Default UAs of `python-requests`, `httpx`, Node `undici`/`fetch`, and bare custom tokens get a 403 HTML notice; curl, Go and `Mozilla/5.0 (compatible; name/ver; +url)` pass. The server must set an accepted UA; behaviour may change without notice. Spoofing a full browser UA was not tested (not appropriate).
3. **Landing/product pages are not content.** `/docs/en/<product>/<ver>` is either a JS shell (WCA) or a "Bot Index" link page (Db2, Bob Z); unknown `?topic=` slugs also fall back to the Bot Index with HTTP 200 — detect by `<title>… - Bot Index` or size.
4. **Entitled content.** `product.isEntitled` / search `search/watson` paths require IBM ID; a few products (`isEntitled:true`) will return 401/403 — surface that rather than retry.
5. **Large payloads.** TOC JSON up to ~3 MB; per-product sitemaps up to ~4 MB; cache on disk and summarize.
6. **No official IBM Docs MCP server exists** (IBM/mcp catalog has none; npm/PyPI have none); community ones are single-product, low-maintained, or Playwright-based. A generic server built on `search` + `content` + `products` would be new.
